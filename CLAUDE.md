Any architectural change — protocol types, the Solver interface, error taxonomy, backend selection, packaging — requires reading ROADMAP.md first, and saying which roadmap item it serves. ROADMAP.md is the high-level intent; PLAN.md is the narrower APBS implementation plan beneath it, and where they disagree the roadmap wins. Their phase numbering differs, so always name the document when citing a phase.

This project implements PLAN.md. Backend is the APBS 3.4.1 binary, from conda-forge (what CI tests) or a system package manager, never vendored source and never built here — APBS is compiled, so no Python installer can supply it. Because that pin is no longer enforced by a lockfile, tests/test_corpus.py asserts the version and re-checks the Born energies; treat a corpus diff as a real result change, not a test to regenerate. The sashimi.protocol module is a stable contract for a future native solver (debye) — don't leak APBS concepts above it. Env is uv-managed: uv.lock is the single source of truth for Python, and there is no second package manager. Work through the phases in order; each has an exit criterion.
